# Senselab Core API - Reglas de Desarrollo para Antigravity

Este archivo contiene las directrices, flujos de trabajo y reglas obligatorias para que el asistente de Inteligencia Artificial (**Antigravity**) opere de manera profesional y consistente en este repositorio.

---

## 🔄 Flujos de Trabajo (Workflows)

### 1. Flujo de Refactorización y Planificación (Planning Mode)
* **Requisito:** Para cambios estructurales de base de datos, lógica compleja de negocio o refactorizaciones, siempre se debe generar un plan de implementación (`implementation_plan.md`) y esperar la aprobación explícita del usuario.
* **Refinamiento:** Usar `/grill-me` si hay dudas de diseño para alinear decisiones técnicas mediante una entrevista interactiva.
* **Tareas Autónomas:** Usar `/goal` para sesiones largas o complejas que requieran que el agente resuelva la tarea sin detenerse hasta finalizar.

### 2. Flujo de Pruebas Unitarias y Funcionales (SQLite Testing)
* **Requisito:** Cada vez que se realicen cambios de código o base de datos, se debe validar la suite de pruebas localmente.
* **Comando:** Ejecutar `php artisan test` (que usa la conexión `testing` SQLite en memoria `:memory:` configurada en `phpunit.xml` para máxima velocidad).
* **Para qué:** Prevenir regresiones de código y asegurar que los 800+ tests sigan pasando con éxito.

## 📜 Reglas de Código Obligatorias

### Regla 1: Aislamiento Multi-Inquilino (Multi-Tenancy)
* **Directriz:** Todos los modelos Eloquent de Laravel que manejen datos del cliente deben usar el trait `BelongsToTenant` y tener la columna `empresa_id`.
* **Para qué:** Evita la filtración de datos cruzados en consultas SQL (Data Leakage) entre empresas del ERP.
* **Excepción:** Modelos globales como `RegimenTributario` o `Departamento`.

### Regla 2: Patrón Service Layer (Capa de Servicios)
* **Directriz:** Los controladores de Laravel no deben contener lógica de negocio ni manipulación directa de la base de datos.
  * **Incorrecto:** Escribir `DB::transaction(...)` o consultas complejas de Eloquent en el método `store()` de un controlador.
  * **Correcto:** Inyectar un servicio en el constructor (ej. `private EmpleadoService $service`) y delegar la lógica.
* **Para qué:** Facilita la creación de tests unitarios, desacopla la API HTTP de la lógica interna y reduce el tamaño de los controladores.

### Regla 3: Documentación OpenAPI/Swagger Activa
* **Directriz:** Cada endpoint nuevo o modificado en los controladores de Laravel debe tener sus PHP 8 Attributes correspondientes (`#[OA\Post]`, `#[OA\Response]`, etc.) actualizados.
* **Para qué:** Senselab tiene un 97% de cobertura en Swagger. Si no actualizas las anotaciones, la documentación de la API se desactualiza y rompe la integración con desarrolladores externos.

### Regla 4: Zero Placeholders (Código Real de Producción)
* **Directriz:** Prohibir el uso de códigos `TODO`, respuestas simuladas (mockups) o atajos de prueba en archivos principales, a menos que sea explícitamente dentro de archivos de test (`tests/`).
* **Para qué:** Asegura que cualquier commit generado por el asistente esté listo para ser desplegado en producción de inmediato.
